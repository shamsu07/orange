# Orange architecture

Orange is a native macOS application with a UI-independent conversion library. It targets macOS 13 or later, requires a Swift 6 compiler, and currently compiles in Swift 5 language mode. Development builds have been performed on a macOS 27 host; the deployment target is not evidence of validated macOS 13 runtime behavior.

The public Tangerine reference describes contextual drag wheels and local, source-preserving conversion in its [App Store listing](https://apps.apple.com/in/app/tangerine-file-converter/id6813034065?mt=12) and [website](https://tangerineformac.com/). Orange's implemented subset and unverified requirements are separated in the [parity contract](reference-parity.md). Exact parity and superior performance are goals, not current results.

## Selection and job flow

1. The user selects files through the main window or an observed drag. The UI records file URLs, not uploaded content.
2. A detached worker computes capabilities. Image routes check decodability and installed ImageIO encoders; media routes inspect real streams and FFmpeg encoders. The main actor receives a completed capability snapshot.
3. Compatible outputs/tools are intersected for multiple inputs, then tool visibility is applied per family. Actions have one shared visibility configuration. A hidden selected choice is repaired; a stale unavailable choice cannot execute. Mixed-family Compress is omitted and direct dispatch rejects it before queuing any partial work.
4. Tools requiring a choice open an image, PDF or media coordinator before creating jobs. Confirmed settings are captured with the selected inputs. Ordinary conversions become individual jobs; PDF merging and archive creation receive a grouped selection. `WorkLimiter.shared` admits at most two conversion/preview workers across batches and panels. Blocking native or subprocess work runs away from the main actor.
5. The converter stages and validates output, publishes it without replacing existing files, and returns output URLs plus any fidelity limitation. The UI records completion/failure/cancellation and optionally reveals the results in Finder.

The wheel observes a left-drag plus configured modifier, then arms a native destination under that event's pointer location. Only `NSDraggingInfo.draggingPasteboard` supplies file URLs; its sequence number binds one selection. A named pasteboard change is neither a gate nor a fallback. This replaces 0.1.2's invalid assumption that a copied global mouse-down event always precedes Finder publishing its drag data. Each gesture has an identity that guards deferred releases and capability results. Event snapshots carry their own timestamps, modifiers and coordinates; older copies cannot mutate a later gesture. A temporary movement monitor recovers a consumed mouse-up only while the receiver is armed. Returning to another app dismisses a released picker without canceling a Finder-owned drag. See [0.1.3 verification](verification-0.1.3.md).

Verified native drag files latch after release and require a fresh matching mouse-down/up or explicit keyboard/accessibility confirmation. Hover and drag release never run an operation. Binding a Finder interaction orders out Orange's main and Settings windows; release presents the picker without explicitly activating the app or reopening either window. AppKit can still activate Orange when the picker becomes key. The user-visible requirement is that its primary windows stay hidden, not that the application can never activate. This focus change still needs final native acceptance.

Missing/changed native files or an unexpected replacement session cancel instead of using cached inputs; known retired callbacks are ignored. Destination callbacks never return move/delete operations. Reopening the same selection restores interaction after reset; unchanged capability refreshes preserve the current page. Preview closing resets its controller state. Dialogs and sharing are deferred until the drag callback returns. AirDrop sessions retain their service and source window until a delegate result; clipboard actions report success and sharing/Terminal failures are surfaced.

The wheel uses passive event monitoring rather than suppressing or rewriting Finder drag events. Default shortcuts are Shift/Command/Control for conversion/tools/actions. Each is configurable among eight combinations: Shift, Command, Control, Option, Option + Shift, Command + Shift, Control + Shift, and Option + Command. A wheel shows at most eight choices per page; retapping its active shortcut cycles pages.

The rewritten overlay uses rounded annular sectors, a transparent center, a small central label pill and a 252-point default diameter, clamped to 220...560 points. That default is inferred from a user-provided 504-pixel native reference capture at 2× scale, not from a verified numeric reference preference. For image conversions, wheel choices use the observed clockwise ordering JPEG/PNG/WebP/HEIC/TIFF/AVIF/BMP/PDF, omit a shared source format and filter actual capabilities; thus a PNG input presents JPG at the top, followed by WebP/HEIC/TIFF/AVIF/BMP/PDF when available. Supported archive formats follow those image formats on subsequent pages as needed. The wheel uses the JPG label; manual operation labels retain JPEG. The manual converter retains its full supported-output list.

Glass uses a native backdrop with translucent sector/center overlays; Solid disables the backdrop and makes those surfaces opaque. Reduce Transparency also selects opaque surfaces. Visible previews update after appearance/size changes and accessibility display notifications; normal hover does not reposition the wheel. These rendering corrections address a user-reported defect and still need final native comparison across light/dark modes.

A color fade highlights fixed targets and honors Reduce Motion. Haptics default on with a separate toggle and use AppKit's alignment pattern, gated to one pulse per 90 ms. Public AppKit APIs do not expose intensity; hardware determines the actual sensation. Original soft alternating tones work during the held drag, picking and preview. The wheel prepares two PCM buffers and an output-only AVAudioEngine before highlighting, then schedules buffers without file access or waveform generation on hover. Dismissal stops/releases the engine. A 45 ms sound gate suppresses boundary jitter without queuing delayed feedback; repeated updates within one target are silent. The user confirmed click-like haptic output in 0.1.4 and requested retaining it; it is not a custom vibration. Perceived latency and reference sound/timing parity remain unmeasured.

Native user evidence includes a reference wheel shown during a real held drag. Earlier Orange checks observed onboarding, the 252-point Settings slider, fixed-target preview selection, a completed image rotation, a floating shelf and the system AirDrop chooser, cancelled without sending. The user confirmed held-drag tones and release persistence, then found unreliable activation. The final 0.1.4 user check passed first attempts for all three modes. The earlier intermittent failure was not captured or causally diagnosed; this does not establish repeated app/file-switch reliability. Controller regression tests do not establish reliable native delivery. Real login approval/reboot, display edges and multiple displays also remain unverified; see [0.1.3 verification](verification-0.1.3.md) for the failed native acceptance history.

## Backend boundaries

ImageIO/Core Graphics provide still-image decoding, orientation handling, encoding and PDF creation. Availability is queried rather than inferred from names. WebP uses a native encoder when present, otherwise a verified FFmpeg/libwebp fallback; that fallback limits each side to 16,383 pixels and removes descriptive metadata. Four targeted WebP tests passed, with broad color/metadata qualification still incomplete. Animated and multipage sources are rejected. Vision handles image text recognition and QR reading. PDF text export reuses the shared Vision execution helper, which attempts acceleration and supported CPU/revision fallback paths.

Resize reads display-oriented dimensions, validates a 1...16,384-pixel long-edge target and never enlarges images. It chooses a meaningful smaller default, shows resulting dimensions and skips inputs already within the chosen bound instead of reporting unchanged copies as a resize. Crop uses a normalized rectangle measured from the oriented image's top-left, with draggable corners/movement, aspect presets and numeric adjustments. JPEG/HEIC Compress changes encoding quality while preserving pixel dimensions; it is distinct from Resize, which reduces pixel count. PNG is not offered a lossy quality-compression tool.

Image dialogs debounce estimates for 250 ms, perform actual temporary encodes with the chosen settings and display original bytes → approximate encoded bytes. No-savings compression cannot be confirmed or published as a successful reduction. Estimates are not final-size guarantees: export re-encodes after confirmation. Temporary preview ownership and cancellation are separate from published outputs.

PDFKit loads PDF documents and supports text-layer extraction, page copying, merge/split, and rewriting. Core Graphics renders each exported image page sequentially at 300 DPI, independently of the image Resize setting. `ConversionSettings.pdfMaxDimension` defaults to 10,000 pixels on the long edge, with a hard 10,000-pixel per-side ceiling and 40-million-pixel limit. A smaller explicit PDF bound reduces the raster resolution; the 40-megapixel check rejects oversized page rasters. Exported images include the effective DPI metadata. A default A4 page is approximately 2,481 × 3,508 pixels. The shared renderer applies the PDF drawing transform, including page rotation.

For TXT/MD export, a nonblank page text layer is used directly. Otherwise the page is rasterized at up to 150 DPI with a 2,400-pixel long-edge bound and processed by an accurate local Vision text-recognition request. Pages are processed sequentially with per-page autorelease pools; text and OCR results retain page order, including blank-page separators. Entirely unreadable/blank documents fail before output publication. This is page-level fallback: a page containing some digital text does not also OCR its embedded images. OCR can contain errors, and this does not reconstruct layout, generate a searchable PDF, or produce editable Office documents. No model download is requested by the converter.

PDF Split defaults to a single split-after-page choice and offers custom page ranges as an explicit alternative. Every page must appear exactly once in the partition. A two-page source can split into two single-page files; larger sources require a deliberate partition rather than silently producing one file per page. Page copying preserves page rotation and document information; this is not a general PDF organizer.

PDF Compress is an explicitly destructive raster reduction, not a lossless rewrite. The dialog measures a temporary PDF at the chosen resolution/quality, shows original → estimated bytes and requires an unchecked consent control before saving. Rasterization loses searchable text, vectors, links, forms, annotations, accessibility tags and signatures. The renderer bounds each page to 6,000 pixels on the long edge/40 million pixels, supports 36...300 DPI and processes pages sequentially. Only outputs smaller than the original are eligible. Metadata removal remains a separate operation that clears selected document-information fields and reopens the output to verify their absence; embedded metadata can remain.

Native attributed strings import TXT/Markdown, RTF, DOC and DOCX and export TXT/MD/HTML/RTF/DOCX. HTML import is intentionally unavailable because native HTML importing can involve WebKit, remote resources, and main-thread constraints. Markdown is treated as source text. Rich office layout fidelity is not guaranteed. Pages, EPUB, presentations and binary spreadsheet formats have no backend.

Subtitle parsing validates timestamps, supports long-hour timestamps and preserves cue payloads. VTT exports include the required header. VTT-to-SRT reports loss of positioning, identifiers, style and region metadata that SRT cannot represent. TXT exports omit timing/structural blocks. CSV/TSV parsing recognizes quoted fields, escaped quotes and embedded line breaks, rejecting malformed quoting instead of silently splitting data.

Archive creation calls macOS `zip`, `tar` or `gzip` directly, with argument arrays and controlled working directories. Create ZIP is available as a Control action for multiple selected items. ZIP/TAR can combine items from different parent folders; duplicate top-level names are rejected before writing. Selecting a folder together with one of its descendants is also rejected, preventing overlapping content and an archive stage from being included in its own input tree. Relative entry names avoid recording absolute source paths. Symbolic links are archived as links rather than followed into external directory trees. GZIP operates on a staged copy. No archive is extracted or executed, and archive-to-archive transcoding is unavailable.

Details is an explicit Control action with a retained, nonmodal panel and copy button. Its background worker reads file sizes/dates/permissions/type, bounded image metadata and oriented dimensions, PDF information, or media stream properties. Folder contents are not recursively scanned; symbolic links show their destination. This is an inspection snapshot, not a claim to expose every filesystem or format-specific field. Terminal opens a selected folder or a file's containing folder through the system workspace API.

The backend build now includes source-built FFmpeg 9.0.2, ffprobe and libwebp 1.6.0, with matching archives, configurations, LGPL/BSD and patent notices copied under `Contents/Resources/Tools/share/`; see [backend build notes](ffmpeg-build.md). Native image/document work remains usable without it in a source-only build. Discovery prioritizes an explicit absolute `ORANGE_BACKEND_DIR`, then bundled tools, then PATH/standard locations. The application does not download or install converters. The explicit backend build script downloads pinned official archives.

Menus depend on real encoders and available audio/video streams. The bundled build disables network, GPL/nonfree components and external codec autodetection; MP3/Opus/WebM output is not guaranteed. A media conversion selects the first applicable streams rather than promising every track, subtitle, attachment or chapter. Native Vorbis output explicitly uses stereo. Technical container fields can remain after descriptive metadata removal. Third-party licenses remain separate from Orange's MIT license.

Snapshot, Trim and Change speed use a per-file timeline rather than silent default timestamps. A bounded decoded frame preview follows scrubbing; native playback is available when AVPlayer supports the source. Snapshot begins near the middle, Trim exposes start/end controls, and Speed shows the resulting duration and preview rate. Each selected file must be reviewed before a batch can export. Compression exposes encoding quality; it does not promise savings for already-efficient media.

Video speed changes scale timestamps and the output frame rate together so low-frame-rate sources are not rounded back to the original duration. Output uses constant frame rate derived from the source's average rate × speed. **Variable-frame-rate cadence preservation remains unqualified**; this path is not a lossless timestamp-only edit. Audio uses tempo filters. Snapshot frame rendering is debounced for 140 ms and bounded to 960 × 540 pixels; the saved snapshot uses the export path rather than the preview's reduced resolution.

## Resource limits and cancellation

`WorkLimiter.shared` supplies two permits shared by conversion jobs, option preparation, image encoding estimates, PDF reduction previews, FFmpeg frame previews and Details loading. It releases permits on errors/cancellation; a cancelled waiter must not start expensive work. This is a conversion/preview budget, not a total process/thread count: capability discovery and native AVPlayer playback have separate lifecycles. Each FFmpeg job uses a decoder/encoder thread limit of `min(4, max(1, activeProcessorCount / 2))` and two filter threads. Encoder and media probes are cached; probe subprocesses have ten-second timeouts. Image and video frame sizes are bounded to 40 million pixels, with a 32,768-pixel per-side limit. PDF pages have their separate rendering limits above.

Text/subtitle/delimited-text readers and native RTF/DOC/DOCX import preflight a regular input file with a maximum size of 128 MiB before loading or invoking the native importer. The plain-text reader checks the loaded byte count again before decoding. DOCX additionally passes a ZIP/XML package guard before AppKit import: package entries and actual expansion are bounded, XML parts have a separate limit, and unsafe paths, unsupported/encrypted structures, XML entities and non-hyperlink external relationships are rejected. This guard is a specific input boundary, not a comprehensive security certification. These converters remain in-memory implementations; input/expansion limits do not bound every allocation inside a native importer.

`ProcessRunner` launches executable URLs without a shell, drains stdout and stderr concurrently, and retains bounded diagnostics. Task cancellation terminates the child process and escalates to a kill if it ignores termination. FFmpeg/ffprobe receive local protocol and input-format allowlists. Native converters check cancellation at safe boundaries; a synchronous platform call cannot always be interrupted immediately.

`PreviewTaskGroup` retains superseded or closed-panel tasks until they actually finish. Generation checks reject their late results; cancelling a task is not treated as proof its temporary workspace has been cleaned. App shutdown stops new option requests, cancels work and awaits the groups, conversion jobs and capability workers before replying to termination. A filesystem Move already in progress is awaited rather than interrupted during a possible cross-volume copy.

Idle wheel observation is event-driven: there is no periodic idle scan or global pointer-movement monitor. The recovery movement monitor exists only during an armed drag, and global key-down observation exists only while a wheel is visible. Closing panels stops audio/playback and removes media observers; temporary encoders run only for requested work. The final release’s [30-second idle sample](benchmarks/2026-10-23-arm64-idle.json) recorded no CPU-time increase at 0.01-second resolution, stable 151.3 MiB RSS after native workflow use, and no children. Wakeups and battery drain were not measured. This does not establish a battery-life result or zero idle cost.

These controls prevent unbounded job and thread creation; they do not establish target performance. The [v5 synthetic image diagnostic](benchmarks/2026-10-21-arm64-v5-detached.json) recorded 1,152,040,960 bytes peak RSS, with charged physical footprint of 8,193,416 bytes after JPEG work and 9,487,440 bytes at the end. RSS and charged footprint are different metrics; this is not evidence of a 1 GB leak or proof of memory behavior across workloads. No matched-quality Tangerine, photographic, energy or long-running UI comparison has been completed.

## Output and source integrity

`OutputWriter` allocates a unique hidden stage beside the input. A converter writes only to that stage. After a nonempty-output check and cancellation check, Darwin's exclusive rename (`renamex_np` with `RENAME_EXCL`) publishes the completed file atomically, including on volumes without hard-link support. Existing destinations are never replaced; a numeric suffix resolves collisions. A `defer` removes any remaining stage after publication or failure. Some providers additionally reopen, inspect or integrity-test output; validation is provider-specific, not a universal round-trip fidelity guarantee.

PDF multi-output operations track newly published page files and clean them up if the remaining operation fails. Original conversion inputs are preserved. The explicit Move action changes source locations, checks destination collisions before starting, and reports possible partial completion after a later filesystem failure. Clipboard copy stores file references; it does not create another filesystem copy.

## Privacy, state and packaging

Conversion is offline. The application has no accounts, uploads, analytics, automatic converter installation or update downloader. AirDrop invokes the user's selected macOS sharing action; Terminal opens folders through the system workspace API.

Setup completion, Finder-wheel enablement, automatic Finder reveal, Glass/Solid appearance, wheel diameter, separate sound/haptic toggles, menu visibility and the three modifier bindings persist through `UserDefaults`. Haptics default on; successful jobs retain their separate completion sound. Tools are configurable independently for images, videos, audio and PDFs; Control action visibility is shared across files. Shift conversion formats are not user-hidden and remain limited to implemented capabilities. Metadata removal, quality, image dimension, trim range and speed are session defaults. Jobs and floating shelves are not durable state; published outputs remain ordinary files.

First launch shows onboarding. Optional login registration cannot block the setup completion callback; .notFound attempts OS registration instead of displaying the incorrect reopen-app error. Wheel monitoring starts only after the explicit Enable Orange flow completes. The user can request launch at login during setup or Settings; merely reading login status does not register the app. `SMAppService` registration, pending approval and errors are reflected from macOS, with an explicit link to Login Items Settings. Once setup is complete, background launches stay in the menu bar. File jobs use a small nonactivating activity panel rather than opening the main converter for every job.

The separate preferences window has General, Menus, Formats, Compatibility and About tabs, including size/preview and login controls. Formats edits shared session defaults; Menus controls visibility rather than per-format encoding policies. Reference per-format policies, folder policies, Float target selection and Terminal application selection remain incomplete. The native form styling and Orange artwork are original; exact visual matching is unverified.

`bash scripts/build.sh` builds a host-architecture release bundle at `build/Orange.app`, generates original artwork, and signs locally. `open build/Orange.app` launches it. `bash scripts/test.sh` runs core and app tests. Scripts keep caches in `.cache/` and `.build/`. They do not produce a notarized universal release or establish a passing test result merely by existing.

Orange source and original assets use [MIT](../LICENSE). Apple frameworks remain platform dependencies. No Tangerine source, artwork or sound is included. FFmpeg retains LGPL terms; libwebp retains its BSD license and patent notice. Packaging copies the complete app and verifies matching FFmpeg source/licenses/hash. When the FFmpeg configuration enables libwebp, it also requires libwebp source, COPYING/PATENTS/AUTHORS, configuration, URL and verified source checksum. Packaging does not silently notarize the result.

## Acceptance still required

Authorized read-only inspection on 21 October 2026 identified native Tangerine 2.0.2 and its General/Formats controls. A later user screenshot established a seven-option reference image wheel during a real held drag; its 504-pixel circle compared with the old Orange circle's 772 pixels at the stated 2× scale. The 252-point reference diameter is an inference. Automation recovered after the earlier connection failures. Remaining tabs, complete drag/drop/action flows and exact tool behavior still need evidence.

The 0.1.4 source adds choice dialogs, menu visibility, haptics, Details, selection archives, shared preview limits and shutdown ownership. The [0.1.4 verification report](verification-0.1.4.md) records 198 passing regression tests, focused checks after the final PDF text layout edit, native workflow checks, idle sampling and package validation. These scoped results do not qualify all Finder or reference behavior. The [0.1.3 report](verification-0.1.3.md) records the earlier native activation failure. Still required: repeated first-attempt Finder/app-switch tests, primary-window focus behavior, Glass/Solid across display modes, broader haptic UX, fresh installation/login approval, macOS 13 runtime validation, broad color/metadata qualification, variable-frame-rate speed behavior and matched-output performance/energy measurements. Missing implementations include per-format/folder policies, editable-office PDF conversion, general page editing, additional image/audio/video tools, archive extraction, durable recovery and precise progress. See the [parity contract](reference-parity.md).
