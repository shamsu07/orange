# Working on Orange

- Never access files outside this repository without the user’s permission, including neighboring folders, other projects, application bundles and personal files. Keep task files, caches and generated fixtures inside this repository.
- Use native AppKit/SwiftUI controls and background workers for probing and encoding. Preserve original conversion input files; previews belong in isolated temporary workspaces and must be cleaned up.
- Treat Finder event delivery as a native acceptance requirement. Passing injected controller tests does not prove first-attempt activation, focus behavior, audible latency or haptic feel.
- Add tools only when their actual capabilities work. Show the selected settings and meaningful output preview before edits that need a choice. Never present a silent unchanged copy as a successful resize or reduction.
- Preserve cancellation, shutdown, stale-result rejection, output collision handling and the global two-job limit.
- Use focused commits for fixes and features, including meaningful tests. Keep messages short and describe the change. Do not manufacture earlier milestones or backdate history.
- Before committing, inspect the staged diff and include every required source/helper file. Record exactly what was tested; distinguish native checks, automated tests and unverified behavior.
- Run the relevant checks, build the final app, and package that exact bundle. Keep previous release artifacts. Do not publish, notarize, push or transmit files without authorization.
- Keep communication concise and natural. Report known failures plainly.
